# chat-hanbao（hanbao）项目全生命周期管理

> 文档版本：v0.1 · 日期：2026-08-07 · 状态：进行中（阶段 1 构建跑通原版已完成）
> 上游基线：Hanbao v2.0.1（Apache-2.0）

---

## 1. 生命周期阶段

```
规划 → 改造 → 容器化/打包 → 测试 → 发布 → 运维迭代
```

---

## 2. 各阶段定义与准出标准

| 阶段 | 目标 | 准出标准 |
| --- | --- | --- |
| 规划 | 定方向 / 范围 / 文档 | 可行性分析、项目规划、全生命周期三文档评审通过 |
| 跑通原版 | 先完整移植并跑通上游原版 | 本机 Docker 构建成功，8088 可访问，确认改造基线（阶段 0/1） |
| 改造 | 品牌 + 删减 | 包名/CLI/前端/数据目录/遥测改名完成；裁剪后核心聊天跑通；测试通过 |
| 容器化 | 自建瘦身镜像 + compose | 镜像构建成功（体积大幅缩小），本地 Docker 跑通聊天 / 模型 / 持久化 |
| 打包 | FPK | `fnpack build` 出 `.fpk`，生命周期脚本可用 |
| 测试 | 飞牛实测 | 应用中心手动安装成功，8088 可访问，数据持久化，认证生效 |
| 发布 | 上架 | 提交飞牛应用中心审核（或私有分发） |
| 运维 | 迭代 | 备份机制、更新机制、反馈渠道就绪 |

> 与《项目规划》§7 的阶段划分对齐：阶段 0 准备 → 阶段 1 跑通原版 → 阶段 2 品牌改造 → 阶段 3 删减定制 → 阶段 4 容器化 → 阶段 5 FPK → 阶段 6 飞牛实测 → 阶段 7 上架。

---

## 3. 版本管理

- **基线**：Hanbao v2.0.1（记录 commit / 版本，锁定不再自动追上游）
- **hanbao 版本号**：语义化，起始 `v0.0.1`（已确认；首版先以最小版本号标记"移植跑通"阶段）
- **版本标注建议**：`hanbao 0.0.1 (based on Hanbao 2.0.1)`
- **每次发布记录**：基于的上游版本、改动 delta、依赖变更

---

## 4. 上游同步策略

- **策略**：锁定 v2.0.1，独立 fork，不自动 rebase 上游
- **改动记录**：维护 `CHANGES-FROM-HANBAO.md`，逐条列出修改（文件 + 原因）
- **安全补丁**：如需，手动 cherry-pick 上游相关 commit 到 hanbao 分支
- **避免**：大规模 rebase 导致冲突爆炸

---

## 5. 发布流程

1. 本地 `fnpack build` → `hanbao-x.y.z.fpk`
2. 飞牛应用中心 → 手动安装，走 wizard 填端口 / 账号 / 模型 Key
3. 验证：聊天 / 模型配置 / 数据持久化 / 认证
4. 上架：提交飞牛应用中心审核（或私有分发）

---

## 6. 运维与迭代

- **数据备份**：定期备份 `working` / `working.secret` / `working.backups` 三 volume
- **更新**：新版本 fpk 覆盖安装，数据卷保留（升级回调不删数据）
- **监控**：容器状态、端口可达性、磁盘占用
- **反馈**：用户反馈收集渠道（文档 / issue），定期迭代

---

## 7. 风险与回滚

- **镜像回滚**：保留上一版镜像 tag，fpk 升级失败可回退
- **数据保护**：升级前自动备份三 volume（`upgrade_init` 钩子）
- **关键风险**：
  - 改名遗漏导致品牌泄露
  - 裁剪引入运行时报错
  - 镜像过大导致下载慢
  - 上游安全漏洞无法及时同步

---
